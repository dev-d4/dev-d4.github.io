01 — About

Backend people act on the same day

At Säkra VP I write the backend the business runs on and own it once it is live. The clearest example is the client risk model and the API around it: the logic in Python against a SQL data model, deployed on Azure, released through a GitHub Actions pipeline that runs the test suite before anything reaches production, with logging and alerting on it once it is live. It classifies tens of thousands of clients continuously, and people act on the output directly — so a wrong result is visible the same day, and I am the one who gets the call.

The part I find most interesting is getting probabilistic output to where the business can rely on it. I built a production flow where Azure-hosted LLMs read incoming documents and extract the data that downstream processing acts on. Before it was trusted, I built a rule-based baseline and compared the model's output against it. It now runs automatically and has replaced manual document handling. Financial documents, fees and reporting are most of what my code touches.

Most of what I have built started as a manual process I noticed and proposed replacing, not a spec I was handed. That is also how sharpa.se happened: I wanted it to exist, so I built all of it — data model, engine and a TypeScript and React interface — and shipped it to real users alongside a full-time job. Working agent-first with Claude and Codex is a large part of how one person can carry that.
